# 데모와 웹 분석 결과 차이 재검토

> 이 문서는 화면 녹화 비교 시점의 기록이다. 이후 원본 MP4로 재현한 추적 미실행·표시 오류와 실제 모델의 오분류는 [원본 영상 검토](raw-video-validation.md)에 기록했다. 현재 원본 영상 기본값은 사람 검출 40%다.

검토일: 2026-11-14. 원본 [peanutcorn/Deu_Capstone26](https://github.com/peanutcorn/Deu_Capstone26/tree/9dfce34db59ca49442acfa284dd7eb02bc05b7ea)의 HEAD를 다시 조회해 `9dfce34db59ca49442acfa284dd7eb02bc05b7ea`임을 확인했다. 이번에는 체크포인트 확인에 더해, 원본 분류 코드와 실제 웹 워커의 프레임별 결과를 비교했다. 측정 결과는 [demo-regression-results.json](demo-regression-results.json)에 보관했다.

가장 직접적인 원인은 행동 결과의 90% 필터였다. 데모 화면의 **포즈 신뢰도 90%는 행동 분류 임계값이 아니다**. 원본 화면에는 80% 절도 결과도 표시된다. 모델 가중치가 바뀌지 않아도, 입력 포즈·입력 시점·후처리를 바꾸면 결과가 달라진다.

## 모델 파일 확인

- `train/1_behavior/output/kpt_behavior.pth`: 최종 GUI가 기본으로 선택하는 KeypointLSTM **v2**. 위치·속도, 양방향 LSTM, attention, 30시점 입력이다. 원본 저장소의 파일과 SHA-256이 일치한다.
- 루트 `kpt_behavior.pth`: `train/1_behavior/kpt_behavior.pth`와 같은 **v1**이다. v2와 다른 체크포인트이며 동일한 이름이라고 교체하면 안 된다.
- 루트 `model_final.pth`: `model/model_final.pth`와 같은 **ResNet50 + LSTM 장면 분류기**다. 사람별 관절 분류 모델과 입력·출력 범위가 다르다.
- `model/objects.pt`: `stand`, `pos` 두 클래스의 객체 모델이다. 가판대 도난 자체를 분류하는 별도 학습 클래스는 없다. 행동 모델의 `theft`와 손목·가판대·POS를 이용한 규칙은 별개다.
- 기존 저장소의 포즈 파일은 YOLO11n이다. demo-2에 표시된 YOLO11s를 선택할 수 있도록 [Ultralytics 공식 릴리스](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11s-pose.pt)를 받아 로컬에 설치하고 해시를 [모델 목록](model-manifest.json)에 등록했다. **녹화에 사용된 s 파일 자체가 없으므로 그 파일과의 해시 일치까지 주장하지 않는다.**

규칙이 도난 의심을 만드는 경우 원본 GUI는 점수 0.9를 넣지만, 이는 학습 모델 확률이 아니다. 웹은 규칙 사건의 점수를 `null`로 저장하고 `규칙`으로 표시한다. 원래 모델 결과도 `model_result`에 보존한다. 규칙의 4초 계산은 파일의 영상 시간 기준으로 유지해 CPU 속도에 따라 판정 시간이 달라지지 않게 했다.

## 실제 비교 결과

1. 원본 Git 커밋에서 분류기와 관절 연결 함수를 읽어 별도 비교 대상으로 사용했다. 현재 웹 설정(n, 간격 2, 포즈 50%)과 데모 설정(s, 간격 1, 포즈 90%)에 대해 같은 입력 프레임을 검출하고 양쪽 코드에 넣었다.
2. 수정 전 웹 설정에서는 원본 코드가 표시하는 이상행동 관측 355개 중 320개가 90% 필터로 표시되지 않았다. 데모 설정에서도 149개 중 86개가 가려졌다. 이는 **표시되는 프레임·인물 결과 개수**이며 독립 사건 수나 정확도 백분율이 아니다.
3. 수정한 분류기로 저장된 검출 결과를 재생했다. 총 927개 검출 시점(309 + 618)의 모델 클래스·점수가 원본과 일치했다.
4. 실제 FastAPI → 워커 → PostgreSQL → 웹 경로로 demo-2의 618프레임을 모두 처리했다. 행동 신경망 추론 83회, 모델의 이상행동 관측 149개였다. 원본 결과와 다른 프레임은 **0개**였다(클래스 동일, 확률 절대 오차 0.00001 이내).
5. 마지막 실행에서 모델 사건 3건과 규칙 사건 3건을 DB에 저장했다. 모델 사건의 점수는 약 70.87%, 61.58%, 63.42%로, 이전 90% 기준에서는 표시·저장되지 않았을 결과다. 이는 검출된 의심 사건이며 정답 검증 결과가 아니다.
6. Chrome에서 `도난 의심 71%` 표시, 원본/AI 전환 시 재생 위치 유지, 탐색 시 시점에 맞는 결과, 영상 구간 요청 HTTP 206을 확인했다. 영상 비율 1280:940 유지, 관절 지름 약 3.4px 유지, 분석 결과를 늦게 전달했을 때 자동 대기·재개를 확인했다.

## 처리 속도

YOLO의 CPU 초기화가 `torch.set_num_threads(2)`를 다시 7로 덮어쓰는 것을 확인했다. 공식 [추론 콜백](https://docs.ultralytics.com/usage/callbacks/)으로 추론 시작 시 최대 2개 스레드를 유지한다. CUDA 추론에는 이 제한을 적용하지 않는다. CPU에서 불필요한 `half=False` 인자를 생략해 매 프레임 발생하던 사용 중단 예정 경고도 제거했다.

같은 Mac·demo-2·s 모델·매 프레임 설정의 전체 워커 처리 속도는 **4.4 → 7.0 FPS**, 전체 확인 시간은 약 **144.6 → 90.0초**였다. 모델 결과와 사건 수는 유지됐다. 여기에는 두 YOLO 모델, 추적, 행동 분류, API와 DB 처리가 포함된다. 재생 FPS와 추론 FPS는 다르며, 이 CPU에서 24/30 FPS 실시간 추론을 달성했다는 의미는 아니다. 분석이 끝난 파일은 원본 속도로 결과와 함께 재생할 수 있다.

YOLO11n 선택이나 검출 간격을 늘리면 입력·분류 결과가 바뀔 수 있다. 데모 비교에서는 s·480·간격 1을 유지한다.

## 모델이 작동하는지 확인하는 방법

- **워커 배정 대기**: 등록됐지만 워커가 아직 실행을 가져가지 않았다.
- **모델 불러오는 중**: 실행이 시작됐으며 가중치를 읽고 있다.
- **관절 수집 n/30**: 특정 인물의 행동 모델 입력을 모으는 중이다. 30번째 시점부터 추론하고 이후 5개 입력마다 갱신한다. 트랙 ID가 바뀌면 새로 모은다.
- **사람 검출 n회 / 행동 추론 n회**: 실제 호출 횟수다. FPS, 처리 프레임·전체 프레임·진행률도 함께 표시한다.
- 영상 아래 행동 결과는 **현재 재생 시점**, 서버의 통계는 **최근 처리 시점**이다.
- 파일은 **원본**과 **AI 분석**을 전환한다. AI 화면은 결과가 늦으면 대기하며, 원본 화면은 분석과 독립적으로 재생한다.
- 모델 로딩 실패, 영상 단절, 추론 오류, 응답 갱신 지연을 정상/분석 대기로 숨기지 않고 상태로 표시한다.

## 검증의 한계

**demo-2.mp4는 원본 CCTV가 아니라 기존 GUI 화면 녹화다.** GUI 메뉴, 검출 상자, 관절, 과거 예측 라벨이 이미 영상 픽셀에 포함돼 있다. 이번 비교는 이 동일한 녹화 파일을 원본 코드와 웹 코드에 넣은 호환성 검증이다. 녹화 당시 GUI가 읽던 `1도난2.mp4`와 같은 순수 CCTV 입력에 대한 정확도를 재측정한 것이 아니다. 원본 보기를 선택해도 파일에 이미 그려진 선은 지워지지 않는다.

정확도를 수치로 평가하려면 별도로 확보한 원본 영상과 정답 구간으로 클래스별 precision/recall, 사건 단위 오탐·미탐을 계산해야 한다. 이번 수정은 가중치 재학습이나 점수 부풀리기가 아니다. 학습·실행의 저신뢰 관절 처리 차이 등 원본에 존재하던 한계는 [이전 모델 감사](model-audit.md)에 기록돼 있으며, 임의로 입력 분포를 다시 바꾸지 않았다.

실제 RTSP 장비와 물리 웹캠은 이번 검증에 연결하지 않았다. 공통 추론 경로를 수정했으며 실제 장비의 화각·프레임 전달률은 별도 확인이 필요하다. 실행·검증 명령의 Windows와 macOS 버전은 [백엔드 가이드](../../backend/README.md)에 함께 기록했다. 이번 실제 실행 환경은 macOS다.
