# 절도를 흡연으로 분류하는 현상과 재학습 판단

검토일: 2026-11-14. 사용자의 `화면` 소스와 같은 원본 CF 영상으로 현재 KeypointLSTM v2의 전체 180프레임·26회 추론을 다시 실행했다. 실제 검출 결과를 사용했으며 파일 이름이나 예상 행동을 모델 입력에 넣지 않았다.

## 판단

**행동 분류기는 학습 데이터 구성과 전처리를 고친 뒤 재학습하는 것이 필요하다.** 현재 모델이 내는 흡연 결과를 웹이 잘못 번역해서 생긴 문제가 아니다. 객체·관절 검출기와 DeepSORT까지 전부 처음부터 학습할 근거는 없다.

기존 학습 NPZ·학습 로그·전처리 버전이 없어 현재 가중치의 학습을 정확히 재현할 수 없다. 수정된 입력과 시간 라벨로 행동 분류기를 새로 학습한 기준 모델을 만들고, 기존 가중치 미세조정 결과와 독립 검증셋에서 비교하는 방향을 권장한다. 처음부터 새로 학습하는 방법이 미세조정보다 반드시 우수하다는 결론까지 나온 것은 아니다. 이번 작업에서 가중치를 재학습하거나 교체하지 않았다.

## 실제 모델 출력

학습 코드 `LABEL_NAMES`, 서버 `BEHAVIOR_LABELS`, 웹 `labels`의 인덱스는 모두 **4=흡연, 6=절도**로 일치한다. 체크포인트 자체에는 클래스 이름과 학습 이력이 없는 상태 사전만 있어, 과거 학습의 라벨 순서는 실행 코드 이상으로 검증할 수 없다.

| 영상 시점 | 신경망 원시 흡연 점수 | 신경망 원시 절도 점수 | 화면용 보정 후 흡연 점수 | 화면용 보정 후 절도 점수 |
| --- | ---: | ---: | ---: | ---: |
| 34.7초 | 93.30% | 0.99% | 78.45% | 3.51% |
| 39.7초 | 4.86% | 10.15% | 26.98% | 6.26% |
| 44.7초 | 93.77% | 0.81% | 66.81% | 4.55% |
| 46.3초 | 96.19% | 0.49% | 78.56% | 2.92% |

따라서 표시 임계값이나 시간 보정만 바꿔도 올바른 절도 판정이 된다고 볼 수 없다. 점수는 해당 모델의 클래스 출력이며 실제 행동이 맞을 확률로 검증된 수치는 아니다. 전체 클래스 벡터와 비교 재현 결과는 [theft-smoking-diagnosis.json](theft-smoking-diagnosis.json)에 보관했다.

## 확인된 학습 설계 문제

1. **관절 정보만으로 분류한다.** 입력은 17관절의 상자 상대 좌표와 그 변화량이다. 상품·담배의 영상 특징, 손에 든 물건, 실제 결제 여부는 행동 신경망 입력에 없다. 비슷한 팔 동작을 구분하기 어려운 구조적 제약이 있다. 가판대·POS 규칙은 별도이며 이러한 정보를 행동 모델이 학습했다는 뜻이 아니다.
2. **영상 전체에 같은 행동 라벨을 부여한다.** `extract_kpts_video.py`와 `kpt_common.make_windows`는 절도 폴더의 영상이면 모든 30프레임 구간에 절도 라벨을 붙인다. 행동 전 정상 구간이 학습에 섞일 수 있다. 추출기는 매 프레임 가장 큰 사람을 선택해 여러 사람이 있으면 입력 인물이 바뀔 수 있다.
3. **전처리와 증강에 결함이 있다.** 저신뢰 관절을 학습 추출기에서는 정규화 전 픽셀 원점으로, 실행에서는 정규화 후 영벡터로 표현한다. 또한 `dataset_kpt.py`의 좌우 반전은 누락된 x=0을 1로 바꾸고 누락 마스크를 다시 계산한다. 전부 미검출인 30×34 입력을 좌우 반전만 시킨 재현에서 **0이 아닌 좌표 510개**가 생겼다. 추출기 방식만 실행에 복사한 비교도 미탐을 해결하지 못했다.
4. **시간 기준과 독립 평가가 불명확하다.** 현재 원본은 3 FPS이고 30프레임이 10초다. 체크포인트에는 학습 FPS가 없다. `demo_onset.py`는 특정 데모를 반복해 학습 데이터에 넣으며 평가 코드도 같은 데모 목록을 사용한다. 이 가중치가 실제로 그 절차를 거쳤는지는 로그가 없어 확정할 수 없다.

위 항목은 현재 코드에서 확인한 결함·제약이다. 각각이 현재 가중치 오분류의 몇 퍼센트를 설명하는지까지 측정한 것은 아니다. 여러 포즈 모델·전처리 비교를 포함한 원본 6개 검증은 [원본 영상 검증](raw-video-validation.md)에 있다.

## 재학습에 필요한 준비

- 정상 행동, 절도, 흡연과 나머지 유지할 클래스의 원본·정답 라벨을 확보한다. 상품을 보고 제자리에 놓기, 정상 구매, 휴대전화·손을 얼굴 가까이 드는 동작 등 혼동하기 쉬운 정상 구간도 포함한다.
- 동일한 촬영 묶음의 다른 카메라 영상이 학습·검증·시험에 섞이지 않도록 먼저 분리한다. 현재 확인에 사용한 영상은 성능을 증명할 새 시험셋으로 재사용하지 않는다.
- 사건 시작·종료 구간과 대상 인물을 기준으로 시퀀스를 구성한다. 입력 FPS·관절 누락 마스크·정규화를 학습과 실행에서 공유하고 모델과 함께 버전을 저장한다.
- 혼동행렬, 절도·흡연별 정밀도와 재현율, 정상 영상의 오탐과 사건 감지 지연을 검증한다. 이 작업을 거치기 전에는 운영 모델로 교체하지 않는다.

제공된 로컬 자료는 절도 영상 80개와 그 복사본이며 XML 라벨과 다른 행동의 검증 자료가 없다. 이 자료만으로 8개 행동을 안정적으로 구분하는 재학습을 완료할 수는 없다. [AI-Hub 공식 데이터 설명](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71550)은 MP4 원본과 XML 라벨을 안내한다. 원천데이터뿐 아니라 대응 라벨링 데이터도 필요하다.

## 현재 실행에 적용된 가중치 대조

GitHub 원본 HEAD `9dfce34db59ca49442acfa284dd7eb02bc05b7ea`의 GUI는 기본값으로 `train/1_behavior/output/kpt_behavior.pth`를 선택한다. **찾기**에서 지정한 파일은 `VideoThread`를 거쳐 `TrackBehaviorBuffer`에서 읽는다. [원본 GUI 파일 선택 코드](https://github.com/peanutcorn/Deu_Capstone26/blob/9dfce34db59ca49442acfa284dd7eb02bc05b7ea/gui/main_window.py#L525)

`화면1`의 최신 실행이 참조하는 PostgreSQL 모델 기록, 로컬 기본 가중치, 원본 커밋의 기본 가중치에서 SHA-256 `f9412d9d09ffe6be0132bb310725e18aa49fa06bbb79e475b5d08a76e991c41a`가 일치했다. 루트의 동명 `kpt_behavior.pth`는 SHA-256 `18ca0e846519b1db10b1846e531329ff7bd1ce22b674527e618f194e145d5d85`인 v1이다. 다른 파일을 따로 선택해 데모를 촬영했는지는 파일 경로나 해시가 남아 있지 않아 확인할 수 없다.

## 장면 모델 첨부 및 관절 학습 전처리 수정

`model/model_final.pth`와 루트의 `model_final.pth`는 같은 가중치다. ResNet50으로 각 영상 프레임의 특징을 얻고 LSTM으로 세 프레임의 특징을 처리하는 장면 분류기다. 기존 첨부 기능의 8 MiB 제한 때문에 이 파일을 첨부하면 선택이 바뀌지 않았다. 이제 프로젝트 장면 모델과 SHA-256이 일치하면 등록된 `behavior_rgb`를 선택한다.

키포인트 학습 추출에서 미검출 관절을 (0, 0)으로 유지하도록 수정했고, 좌우 반전에서도 누락 마스크를 유지하도록 고쳤다. 기존 NPZ에는 수정 전 입력이 저장돼 있을 수 있으므로 재학습에 앞서 새 학습 데이터를 생성해야 한다. 기존 폴더 단위 추출을 그대로 사용하면 영상 전체에 동일한 라벨이 붙으므로 사건 구간 라벨과 대상 인물을 먼저 확정해야 한다.
