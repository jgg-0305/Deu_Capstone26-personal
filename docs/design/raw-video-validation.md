# 원본 영상 검증과 추적 끊김 수정

검토일: 2026-11-14. 이번 검증에는 `demo-1.mp4`, `demo-2.mp4`를 사용하지 않았다. 사용자가 지정한 AI-Hub 데이터셋 폴더의 **원본 MP4**로 테스트했다.

## 결과

**추론이 실행되지 않는 원인과 관절 표시가 끊기는 원인은 수정했다. 그러나 현재 가중치의 실영상 분류 정확도는 충분하지 않다.** 특히 사용자가 등록한 `C_3_12_41_BU_DYA_07-29_15-20-29_CF_RGB_DF2_F2.mp4`는 수정 후에도 절도를 흡연·넘어짐으로 오분류한다. 사건이 DB에 저장된 사실과 사건을 올바르게 분류한 사실을 구분해야 한다.

- 기존 설정: 선정한 원본 영상 **6개 모두 행동 모델 실행 0회**.
- 수정한 기본 설정: 6개 모두 행동 추론 실행. v2 추론 횟수 합계 **144회**.
- v2에서 절도 점수 60% 이상 결과가 나온 파일: **3/6**.
- v1에서 같은 조건의 절도 결과가 나온 파일: **4/6**.
- 장면 모델 `model_final.pth`: **0/6**. 추론 1,068회가 모두 정상 클래스였다.

위 비율은 파일 안에서 해당 출력이 한 번이라도 나왔는지를 센 것이다. **정확도, 재현율, 올바른 사건 감지율이 아니다.** 한 영상에는 정상 행동 구간도 있고, 조기 판정·잘못된 클래스·판정 지연이 확인됐다. 정답 시간 구간 XML과 정상·다른 행동 검증셋이 현재 폴더에 없으므로 정식 성능 수치를 만들지 않았다.

## 입력 확인

[AI-Hub 데이터 설명](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71550)의 데이터 형식은 MP4이고 라벨 형식은 XML이다. 지정된 로컬 폴더에는 `combined_video_data`의 MP4 80개, `extracted_images`의 같은 이름 MP4 80개, ZIP과 분할 ZIP만 있었다. XML은 없었다. 두 폴더를 160개의 독립 검증 영상으로 계산하지 않았다.

3개 촬영 장소, 5개 촬영 묶음에서 서로 다른 각도를 포함한 6개 영상을 골랐다. 선정 파일은 [raw-video-test-set.json](raw-video-test-set.json)에 고정했다. 6개 모두 **1920×1080, 3 FPS, 180프레임, 60초**였다. 총 1,080개 원본 프레임을 빠짐없이 처리했다.

사용자가 올린 CF 파일의 CRC32는 ZIP 내부 항목과 로컬 추출본 모두 `3321997141`이었다. 이 파일의 3 FPS는 이번 웹 분석에서 변환한 결과가 아니다. 낮은 프레임률 자체를 표시 보정으로 30 FPS 영상으로 만들 수는 없다.

## 끊김과 미실행의 원인

1. **220ms 고정 유효 시간.** 3 FPS 영상은 한 프레임이 약 333ms 동안 표시된다. 웹은 결과가 220ms보다 오래되면 숨겨 다음 영상 프레임까지 관절 표시가 사라졌다. 이제 원본 FPS와 검출 간격으로 `frame_duration_ms`를 전달하고 그 유효 시간까지 같은 프레임의 결과를 유지한다. 새로운 결과가 없다고 오래된 표시를 무기한 유지하지는 않는다.
2. **사람 검출 90%를 일반 영상 기본값으로 사용.** 데모 화면을 재현하기 위한 높은 검출 기준 때문에 원거리·기울어진 사람 검출이 자주 빠졌다. 그 기준에서 6개 모두 30프레임 시퀀스를 완성하지 못했다. 일반 원본 영상 기본값은 40%, 데모 비교용 설정은 별도 버튼으로 분리했다. 행동 표시 50%와 사건 저장 60%는 변경하지 않았다.
3. **한 번의 미검출로 행동 기록 삭제.** `HumanTracker.update([])`가 빈 목록을 반환하고, 행동 버퍼는 목록에 없는 ID를 즉시 삭제했다. 이제 추적기는 확정 ID를 소실 허용 기간 동안 유지한다. 행동 버퍼는 짧은 누락을 미검출 벡터로 기록하고 기존 수집 내용을 보존한다. 긴 누락 뒤에는 새 시퀀스를 수집한다. 보이지 않는 사람에게 새 행동 판정을 만들지 않는다.
4. **관절과 사람의 별도 재매칭.** 겹친 상자에 대해 별도 IoU 매칭을 하면 서로 다른 트랙에 같은 사람의 관절이 들어갈 수 있다. [DeepSORT의 검출 부가 정보 연결](https://github.com/levan92/deep_sort_realtime#supplementary-info-of-original-detection)을 사용해 실제 연결된 검출의 관절과 상자로 분류한다. 미관측 트랙은 점선 상자로 표시하며 다른 사람의 관절을 가져오지 않는다.
5. **실제 입력 시간과 표시 혼동.** 3 FPS 영상에서 30프레임은 10초다. 화면에 입력 FPS, 처리 FPS, 분류 입력 시간을 따로 표시한다. 신뢰도가 기준에 못 미치는 이상행동 후보를 확정된 정상으로 표시하지 않고 `판정 보류`와 실제 후보 점수를 보여준다.

## 모델별 실측

설정은 YOLO11s, 해상도 480, 사람 검출 40%, 매 프레임 입력, 행동 표시 50%, 사건 저장 60%다. 동일한 실제 포즈 검출을 두 키포인트 모델에 넣었다. 장면 모델은 같은 원본 프레임을 입력받았다. 파일 이름·예상 행동은 분류기에 전달하지 않았다.

| 번호 | 원본 파일 식별부 | v2 추론 | v2 절도 출력 ≥60% | v1 절도 출력 ≥60% | 장면 모델 |
| --- | --- | ---: | --- | --- | --- |
| 1 | 41 · DYA · CD | 29회 | 있음, 54.0초부터 | 있음 | 정상만 출력 |
| 2 | 41 · DYA · CF — 사용자가 등록한 영상 | 26회 | 없음 | 없음 | 정상만 출력 |
| 3 | 43 · DYB · CA | 18회 | 없음 | 없음 | 정상만 출력 |
| 4 | 45 · SMC · CC | 24회 | 있음, 44.7초부터 | 있음 | 정상만 출력 |
| 5 | 48 · DYA · CE | 26회 | 없음 | 있음 | 정상만 출력 |
| 6 | 49 · DYB · CB | 21회 | 있음, 12.7초부터 | 있음 | 정상만 출력 |

원본 CF 영상의 36초 부근에는 진열대에 손을 뻗는 동작, 39~42초에는 손에 든 상품을 보는 동작, 45초 부근에는 주머니 가까이 손을 옮기는 동작이 보인다. 해당 영상에서 v2는 흡연·넘어짐을 출력한다. 현재 키포인트 모델의 결과를 실제 상품 반출·결제 여부의 증거로 볼 수 없다.

YOLO11n·640으로도 같은 6개 원본 영상을 별도 실행했다. v2 절도 출력 파일 수는 여전히 3/6이고 CF 영상에서는 절도 출력이 없었다. 포즈 모델 선택이나 해상도 변경만으로 문제가 해결됐다고 볼 수 없다.

`model_final.pth`는 학습 코드의 `LSTM_NIA`를 따로 구성해 같은 가중치와 BGR 전처리로 비교했다. CF 영상 15초·27초·42초의 3프레임 입력에서 학습 코드와 웹 코드 모두 **정상 83.66048%**를 똑같이 출력했다. 조사한 입력에서 장면 모델이 정상만 출력하는 현상은 웹의 클래스 표시가 누락돼서 생긴 현상이 아니다.

### 학습·실행 입력 차이 추가 검증

원본 `kpt_common.py`는 낮은 신뢰도의 관절을 픽셀 원점으로 바꾼 뒤 상자 기준으로 정규화하므로 음수 좌표가 나온다. 실행 분류기는 같은 관절을 최종 특징 `(0, 0)`으로 둔다. 하지만 학습 증강의 마지막 단계에서는 좌표를 `[0, 1]`로 제한한다. 따라서 추출기 출력만 실행에 복사한다고 실제 학습 입력과 같아진다고 단정할 수 없다. 체크포인트에는 학습 데이터와 전처리 실행 이력이 들어 있지 않다.

이 영향을 확인하기 위해 동일한 6개 원본 영상의 실제 YOLO11s·480 검출을 재사용하고, 분류 입력만 원본 추출기의 `encode_kpts` 방식으로 바꿔 두 행동 모델을 다시 실행했다. v2는 절도 60% 이상 출력이 **0/6**, v1은 **3/6**이었다. CF 영상에서 v1의 절도 출력은 13초부터도 발생해 상품을 다루는 후반 구간과 일치한다고 볼 수 없다. 이 비교로 성능 향상이 확인되지 않았으므로 웹의 기본 인코딩은 기존 실행 방식으로 유지했다. 결과는 JSON의 `training_encoding_diagnostic`에 보관했다.

또한 원본 `demo_onset.py`는 특정 데모 영상과 시작 프레임을 지정해 학습 윈도우를 기본 8회 추가하며, `evaluate_models.py`도 같은 목록을 평가한다. 실제 가중치가 이 과정을 거쳤는지는 기록이 없어 확정할 수 없다. 다만 이 절차를 거쳤다면 해당 데모에서 보인 결과는 독립적인 성능 검증이 아니다. 데모 품질이 다른 원본 영상에 그대로 이어진다고 판단할 근거로 쓰지 않았다.

## API·DB·브라우저 검증

- 실제 업로드 → FastAPI 대기열 → 워커 → PostgreSQL 경로로 CF 영상과 CB 영상을 분석했다. 두 영상 모두 180프레임을 완료했다.
- CF 영상: 행동 모델 26회 실행. 흡연 3건, 넘어짐 1건이 DB에 저장됐다. 이 결과를 올바른 절도 감지로 계산하지 않았다.
- CB 영상: 행동 모델 21회 실행. 절도 의심 모델 사건 2건이 저장됐다. 사건이 나온 시간과 원본 동작은 추가 정답 검증이 필요하다.
- 사용자의 기존 `화면` 소스도 원본 영상 기본값으로 재분석했다. 원본 파일, 계정 소유권, 이전 분석 기록은 유지했다.
- Chrome에서 원본 CF 영상을 30.3초로 탐색했다. 프레임 시작 이후 220ms가 지난 위치에서도 영상과 관절 표시가 유지됐다. 이어서 재생 중 25번 확인한 화면에서 유효한 결과가 불필요하게 사라지는 경우는 0번이었다.
- 실제 원본 해상도, 입력 3 FPS, 행동 추론 26회, 분류 입력 10초, 판정 보류 표시를 확인했다.
- Python 회귀 검사 9개, 프런트엔드 시간축 검사 3개, React 빌드가 통과했다.

기계 판독 가능한 결과·파일 해시·모델별 분포는 [raw-video-validation-results.json](raw-video-validation-results.json)에 기록했다.

## 남아 있는 모델 품질 작업

현재 받은 자료는 절도 폴더의 원본 영상이며 정답 구간 XML이 없다. 단순히 임계값을 더 낮추거나 절도 클래스만 강제로 선택하는 방법으로 해결하지 않았다. 원본 가중치도 덮어쓰지 않았다.

실제 모델 품질 개선에는 정상과 각 이상행동의 라벨·정답 시간 구간을 확보하고, 같은 촬영의 여러 카메라가 학습·검증에 섞이지 않도록 분리한 재학습·독립 평가가 필요하다. 포즈 입력의 프레임률, 저신뢰 관절 처리, 객체와 상호작용을 나타내는 정보도 학습·추론 양쪽에서 일치시켜야 한다. 이전의 화면 녹화 비교 결과를 이 실영상 검증의 대체 근거로 사용해서는 안 된다.

재실행 명령은 [Windows·macOS 실행 가이드](../../backend/README.md#원본-데이터셋-재검증)에 있다.
